為什麼要做這個工具？

以往的痛點 vs 現在的解法

❌ 以往（手動製作）

  • • 設計師一個一個手動排版、打字
  • • 容易漏放圖片或放錯零件圖
  • • 手動輸入尺寸容易打錯
  • • 每台機台重複操作，耗時費力
  • • 修改一個零件要重新調整整頁排版

✅ 現在（AI 工具）

  • • AI 自動辨識圖片上的尺寸文字（OCR）
  • • 拖放即完成排版，不需手動打字
  • • 零件清單自動生成，不會遺漏
  • • 換機台只需替換素材，結構自動套用
  • • 紅線自動閃避卡片（A* pathfinding）
  • • 隨時拖動調整，紅線即時重算

7 個讓匯出結果壞掉的 Bug

預覽正常 ≠ 匯出正常

❌ Bug #1

紅線穿過卡片不閃避

指示線直接穿越其他零件卡片，視覺混亂

❌ Bug #2

匯出材質索引表結構不同

Canvas 2D 重畫的表格跟 HTML 顯示的欄位數量不一致

❌ Bug #3

匯出圖片被拉伸變形

html2canvas 不支援 object-fit，裁切後圖片比例跑掉

❌ Bug #4

匯出右下方大量空白

固定 820×1160 尺寸跟實際 DOM 渲染不一致

❌ Bug #5

紅線出現斜線

A* grid 座標轉像素時產生非正交線段

❌ Bug #6

拖曳卡片紅線不重算

cache 未失效 + A* 效能阻塞主線程

❌ Bug #7

Undo/存檔功能不完整

拖曳移動沒存 snapshot，刷新後排版消失

04

為什麼這麼難修？

每個 Bug 背後都是架構層的矛盾

匯出圖片變形

根因：html2canvas 不支援 CSS object-fit:cover/contain。Canvas 2D 重畫方案又跟 DOM 不一致。
✅ 解法：匯出前將 img 替換成等大 canvas 元素（drawImage 精確繪製 cover/contain），html2canvas 截取像素級完美結果。

紅線穿過卡片

根因：機台圖被當作 A* 障礙物（但紅線本來就要連到機台圖）→ 起終點被 blocked → A* 全部 fallback 到直線。
✅ 解法：機台圖不加入障礙物 + 清除起終點周圍 5×5 格子 + enforceOrthogonal 最終防禦。

匯出 ≠ 預覽

根因：Canvas 2D 重畫整頁（材質表、卡片、紅線）的邏輯跟 HTML/CSS 渲染完全不同 → 結構、順序、間距全部不對。
✅ 解法：放棄「重畫」，改為 html2canvas 直接截取 DOM。看到什麼就匯出什麼 = WYSIWYG。
